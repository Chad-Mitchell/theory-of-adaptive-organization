# Memo: one source per fact, a cost-based fix for repo drift (draft, not implemented)

*Wednesday 25 November 2026 (America/New_York). Counted on `main` at `1eed183` (PR #288). A design memo only: nothing below is implemented, and no file outside this memo changes in this PR. Implementation waits for sign-off.*

> The law of adaptive organization (hypothesis): strongly selected systems minimize the cost of judgment. (`CORE.md:7`)

## 1. The cost applied to the repo

Each fact the repo states is a memory. Its cost per merge is the master-equation sum restricted to three terms (`THEORY.md:26-40`): tracking (\(\kappa I_{\mathrm{mem}}\): every hand-kept copy must be re-edited and re-reviewed when the fact changes), looking up (\(A\): reading the one place that holds it), and stake times error (\(w\,\mathbb{E}[\ell]\): a decision or a public line taken from a stale copy). With \(c\) hand-kept copies of a fact that changes \(r\) times per merge, tracking grows as \(c\,r\), and each unrefreshed copy is wrong at the next decision that reads it.

Two consequences, both observed below:

1. **A fact that changes at every merge cannot be kept by hand.** The `main` SHA changes with every merge, including the merge that writes it, so a committed SHA is stale the moment it lands (\(\mathbb{E}[\ell]\) is 1 per merge, whatever the tracking spend). The minimum is \(c=0\): derive it live (`tools/brief.py` already does) and pay only the lookup.
2. **A fact must sit where the decision is taken.** Work order is chosen from the ranked list (`OPEN_WORK.md` §9). A direction that lives elsewhere (chat, `STATUS.md` "Next", a roadmap note) is not read at the decision, so its error rate is set by its absence, not by its wording.

For facts that change slowly (claim statuses, versions, the Lean total, the queue) the minimum is one hand-kept source, with every other appearance generated from it or deleted, and a check that fails at merge time when a copy disagrees.

## 4. The plan

**Rule.** Each fact has one hand-kept source. Every other appearance is generated from it or deleted. Facts that change at every merge (the `main` SHA, the open-PR list, PR review or merge state) are never committed: `tools/brief.py` prints them live.

**Checks that make drift unmergeable.** All run inside `check_consistency.py` or `check_claims.py`, which pytest already runs on the real tree (`test_check_consistency`, `test_clean_tree_passes`), so a drifted tree fails the full pytest that gates every PR.

1. *No hand pointer* (`check_consistency.py`): a maintained file that states a current `main` SHA (`` `main` is `abc1234` ``, `` on `main` `abc1234` ``), an open-PR list, a PR's merge or review state, or a Lean total in bold fails. Historical "merged as `sha`" lines pass.
2. *Direction* (`check_claims.py`, replacing `check_gap`): §9 must carry the dated direction line and the hypothesis sentence byte-identical; every row's rank is an integer or `parked`; a row tagged `data`, or listed as parked, with an integer rank fails; a `parked` row without a restart condition and a decider fails; rank 1 must be tagged math.
3. *Summaries* (`check_claims.py`, also run by `check_pending.py --body-file`): a sentence in a PR body or in added lines of a maintained `.md` that judges the theory as a whole (its reach, prospects, value, or what a test means for the theory) must cite a ledger row ID in the same paragraph, or it fails.
4. *Own row on merge* (`check_pending.py --pr N`): if `OPEN_WORK.md` on the branch still marks the row for #N "In flight", the PR fails; the PR moves its own row as if it were the one merged.
5. *Views* (`check_claims.py --write`): regenerates the views; the existing mismatch check stays.
6. *CI* (optional): `.github/workflows/checks.yml` running the offline checks and pytest on every PR. It needs a token with the `workflow` scope or Chad adding it in the web UI (`process/FAILURES.md`, `REPO-CURRENT-1` item 3).
